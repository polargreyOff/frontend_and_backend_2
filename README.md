## Практики 7-8

Что реализовано:

- JWT-авторизация
- регистрация и вход пользователя
- защищённые маршруты
- Swagger-документация для API

Основная идея:

- пользователь регистрируется
- получает токен доступа
- использует его для обращения к защищённым методам API

## Практики 9-10

Что добавлено:

- refresh-токены
- обновление пары токенов через `POST /api/auth/refresh`
- хранение `accessToken` и `refreshToken` на фронтенде
- автоматическая попытка обновления токена при `401`
- интерфейс для работы с товарами на React

Основная идея:

- если `accessToken` истёк, фронтенд пробует получить новую пару токенов
- если refresh проходит успешно, исходный запрос повторяется автоматически

## Практики 11-12

Что добавлено:

- доступ на основе ролей (RBAC)
- роли: `user`, `seller`, `admin`
- управление пользователями для администратора
- разграничение прав на действия с товарами

Роли и возможности:

- `user`:
  просмотр списка товаров и просмотр товара по `id`
- `seller`:
  всё, что может `user`, плюс создание и редактирование товаров
- `admin`:
  всё, что может `seller`, плюс удаление товаров, просмотр пользователей, редактирование пользователей и их блокировка

## Практики 13-14

Что добавлено:

- отдельное PWA-приложение для заметок в папке `practice_13-14`
- `Service Worker` для офлайн-режима
- кэширование статических ресурсов
- `manifest.json` и иконки для установки приложения
- хранение заметок в `localStorage`

Основная идея:

- приложение загружается и работает даже без интернета после первого посещения
- заметки сохраняются локально
- сайт можно установить как PWA

## Практики 15-16

Что добавлено:

- запуск приложения по `HTTPS`
- архитектура `App Shell`
- динамическая подгрузка контента из папки `content`
- сервер на `Express`
- `Socket.IO` для событий в реальном времени
- push-уведомления через `Push API` и `web-push`

Основная идея:

- shell приложения кэшируется и открывается быстро
- заметки синхронизируются между вкладками через WebSocket
- пользователь может подписаться на push-уведомления

## Практика 17

Что добавлено:

- заметки с напоминанием по дате и времени
- поле `reminder` в данных заметки
- планирование напоминаний на сервере через `setTimeout`
- action-кнопка в уведомлении для откладывания
- повторное push-уведомление после `snooze`

Основная идея:

- пользователь создаёт заметку с напоминанием
- сервер хранит активные таймеры напоминаний
- при наступлении времени приходит браузерное push-уведомление
- напоминание можно отложить на короткий срок прямо из уведомления

## Запуск проекта

Ниже пример запуска для папки `practice_9-10`. Для `practice_11-12` команды такие же.

### 1. Backend

```powershell
cd practice_9-10\backend
npm install
npm run dev
```

Backend будет доступен по адресу:

- `http://localhost:3000`
- Swagger: `http://localhost:3000/api-docs`

### 2. Frontend

```powershell
cd practice_9-10\frontend
npm install
npm run dev
```

Frontend будет доступен по адресу:

- `http://localhost:5173`

## Запуск PWA-практик

### Практики 13-14

Статическое приложение лежит в папке `practice_13-14`.

Пример запуска:

```powershell
cd practice_13-14
python -m http.server 8080
```

Адрес:

- `http://localhost:8080`

### Практики 15-17

PWA-приложения с сервером лежат в папках:

- `practice_15-16`
- `practice_17-18`

Пример запуска:

```powershell
cd practice_17-18
npm install
npm start
```

Адреса:

- `https://localhost:3001`, если в папке есть `localhost.pem` и `localhost-key.pem`
- `http://localhost:3001`, если сертификаты не используются
